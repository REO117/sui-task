# Sui

Android向けモバイルファーストの、メモ・タスク管理Webアプリ。

[公開アプリ](https://sui-task.saymyname710.workers.dev/) · [GitHub](https://github.com/REO117/sui-task)

- 最初の画面にメモ入力欄。ログインも通信も待たずに端末へ保存。
- 右フリックで「メモ → 未着手 → 進行中 → 完了」。左フリックで一段戻る。
- 編集、検索、期限、カテゴリ、ピン留め、ゴミ箱、復元、変更の取り消し。
- 白を基調とするLiquid Glass UI。半透明、背景ぼかし、光沢、ばねの動き。
- 以前のタスクアプリのドット絵レッシィを再利用。待機、声をかけた時の敬礼、AI処理中の考える仕草、タスク完了時の喜び。スマホで文字を入力中は隠れ、設定で表示を切り替えられる。
- 全画面スケルトンの表示中も、メモ入力欄は操作可能。
- 指定した本人のGoogleアカウントだけでログインし、Cloudflare D1へ同期。ログイン方式はGoogleのみ。
- Workers AIでメモをタスク候補に分解。候補を確認してから追加し、元のメモは保持。
- Androidのホーム画面へ追加できるPWA。初回読み込み後はオフラインでメモを扱える。

## 技術選定と理由

| 技術 | 用途 | 選んだ理由・トレードオフ |
|---|---|---|
| React | 画面と入力状態の管理 | 編集・絞り込み・モーダルなどの状態を一貫して扱える。ライブラリの読み込み量は素のJavaScriptより増えるため、ビルド時に圧縮しPWAで再利用する。 |
| TypeScript | フロントとAPIの型 | タスクの項目とステータスを共通定義し、保存形式の食い違いを検出する。型検査は実行時の検証を代替しないためZodも併用。 |
| Vite | 開発・ビルド | 修正を即時反映し、公開用の静的ファイルを生成する。検索流入用のサイトではなく操作中心のアプリなので、初期実装はサーバーレンダリングを採用しない。 |
| Motion | フリック、画面遷移、一覧の並べ替え | ドラッグの追従、速度の判定、ばね、項目移動を統一できる。OSで動きを減らす設定にも対応。 |
| CSS backdrop-filter / gradients | Liquid Glassの見た目 | 画像ではなくCSSで半透明、光沢、背景ぼかしを描画。画面サイズに追従し、不要な画像通信をなくす。非対応ブラウザには不透明に近い背景を用意。 |
| 既存の透明PNG・CSSのコマ切替 | ドット絵レッシィ | 既存アプリの3枚の素材を再生成せず再利用。フレームを切り替えて待機・仕草を表示し、新しい依存関係や外部APIを増やさない。画像はメモ画面の描画後に読み込み、オフライン用にキャッシュ。非表示・入力中・別タブ・モーダル表示中は動作を止める。 |
| Lucide | アイコン | 細い線幅で統一でき、必要なアイコンだけを組み込める。 |
| IndexedDB + Dexie | 端末保存、下書き、同期待ち | 通信待ちをメモ入力から切り離す。同期失敗・再起動でも保存と送信待ちを維持する。ブラウザのサイトデータを消すと未同期分は消えるため、JSON書き出しも用意。 |
| dexie-react-hooks | 保存結果の画面反映 | IndexedDBの変更に画面を追従させ、一覧と件数を同じデータから更新する。 |
| localStorage | オフライン起動時の保存領域の復元 | 最後にログインした利用者の表示情報だけを保持し、通信できない再起動でも同じメモを開く。認証トークンは保存しない。APIにはサーバーの認証が必要で、再接続時に本人確認を行う。ログアウトで表示情報を解除する。 |
| Cloudflare Workers + Static Assets | APIと画面の公開 | 画面、API、認証を同じドメインに置ける。別サーバーの常時運用と、不要なドメイン間通信設定を省ける。 |
| Hono | Workers上のAPIルーティング | Workersの標準Request/Responseに合い、認証・送信元確認・サイズ制限を共通化できる。 |
| Cloudflare D1 | クラウド保存 | 小規模なタスクと利用者データにSQLiteの表形式が合う。全操作を利用者IDで限定する。ファイル保存は要求されていないためR2は採用していない。 |
| Cloudflare Workers AI | メモからのタスク候補生成 | 指定どおりCloudflareからモデルを実行する。プロバイダーの秘密鍵をブラウザに置かず、AI bindingをサーバーだけで使う。 |
| gpt-oss-20b | 初期のWorkers AIモデル | Cloudflareが提供する、応答速度を重視した比較的小さなモデル。タスクの構造化に利用。モデル名は環境変数AI_MODELで変更できる。品質は実際の日本語メモで確認が必要。OpenAI APIへの直接接続ではない。 |
| Google OAuth 2.0 / OpenID Connect | Googleのみの本人確認 | Googleのパスワードをアプリに渡さない。コード交換はWorkerで実施し、Googleの署名、発行元、対象アプリ、nonceを検証する。取得範囲はopenid/email/profileのみ。 |
| jose | Google IDトークンの検証 | 公開鍵による署名検証を既存の暗号ライブラリに任せる。独自の暗号処理を作らない。 |
| HttpOnlyセッションCookie | ログインの継続 | ブラウザのJavaScriptからセッション値を読めない。サーバー側ではトークンのハッシュだけを保存。有効期間30日。 |
| 本人限定の許可リスト | ログイン利用者の制限 | Google側のテストユーザーを本人だけにし、Workerでも検証済みメールアドレスを照合する。許可先が未設定ならログインを拒否し、許可されていない既存セッションも拒否する。本人のメールアドレスはCloudflareのsecretに置き、公開コードには含めない。 |
| Zod | API入力とAI応答の検証 | 不正なステータスや空メモ、AIの壊れた応答を保存前に拒否する。 |
| vite-plugin-pwa / Workbox | ホーム画面追加・オフライン | アプリの画面をキャッシュし、Androidで単独アプリのように起動する。API・認証はキャッシュの対象外。 |
| Vitest + fake-indexeddb + Miniflare | 自動テスト | 端末保存と同期競合を再現し、D1の実SQLで利用者分離・更新・復元・認証保護を検証する。AIのスタブテストと実接続テストは区別する。 |
| Wrangler | Cloudflareへの公開とDB移行 | Cloudflare公式の開発・公開ツール。ローカル設定はAIに接続せず、実モデルを使ったふりをしない。 |
| Git / GitHub | コードの履歴と公開 | アプリ専用の独立したリポジトリを使う。業務フォルダ、顧客情報、秘密鍵、端末データは含めない。 |

## 起動

Node.js 24以降を推奨。依存関係の正確なバージョンはpackage-lock.jsonに固定。

```sh
npm ci
npm run db:local
npm run dev:api
# 別のターミナル
npm run dev
```

画面は `http://127.0.0.1:5173`。ローカルAPIは8787番。
未接続でも端末内のメモは使える。公開アプリではGoogle認証・Workers AIの実接続を確認済み。ローカル設定だけではこれらの実接続は有効にならない。

## データと同期

端末の保存を先に完了し、ログイン済みの変更を送信待ちへ積む。初回ログインでは未ログイン時のメモと下書きを、ログインした利用者の保存領域へ移す。ログアウトするとその利用者の一覧を表示しなくなる。同期は保存時、オンライン復帰時、画面復帰時、15秒ごとに試みる。

新しい公開版がある場合は更新ボタンを表示する。下書きの保存完了を待ってから更新し、編集画面やAI処理の途中で自動的に再読み込みしない。

競合は更新日時が新しい内容を採用。5分を超えて未来の時計の更新はサーバーが拒否する。同時編集を文字単位で統合する共同編集ではない。削除は墓標を残して同期し、ゴミ箱から復元できる。ログイン済みデータはGoogle利用者IDごとに分離し、利用者IDをクライアントの申告だけで信用しない。

AI実行は利用者ごとUTC日付で1日30回まで（失敗した呼出も含む）。メモ本文は「AIで整理」を押した場合のみWorkers AIへ送る。モデルの出力は検証し、追加操作までD1にタスクを作らない。元のメモは自動では削除しない。

「テスト」のような短い作業名や、買い物の箇条書きも整理対象にする。作業を特定できず候補が0件になった場合は通信失敗にせず、内容を補う案内を表示する。応答形式の違い、結果の途中切れ、応答待ちの時間切れ、接続障害も区別する。GPT-OSSの推論量はlow、出力上限は4,000トークンに設定し、短い整理に推論時間と出力枠を使いすぎないようにしている。
